## 一、ReAct 框架：Agent 的"思考-行动-观察"循环

### 1.1 ReAct 是什么？

**ReAct = Reasoning（推理）+ Acting（行动）**

ReAct 是一个让 AI 像人一样"边思考边行动"的框架。

**人类解决问题的方式：**
```
遇到问题
↓
思考：我需要什么信息？
↓
行动：去查资料、做实验
↓
观察：结果是什么？够不够？
↓
[循环] 如果不够，继续思考和行动
↓
得出结论
```

**ReAct 让 AI 也这样做：**
```
用户查询
↓
Thought（思考）：分析问题，制定计划
↓
Action（行动）：调用工具获取信息
↓
Observation（观察）：评估结果质量
↓
[循环] 判断：信息是否充足？
↓
Final Answer（最终答案）
```

### 1.2 ReAct 的完整流程图

```
┌──────────────────────────────────────┐
│         用户输入查询                  │
│  "孙悟空和猪八戒谁更厉害？"           │
└────────────┬─────────────────────────┘
             │
             ▼
   ┌─────────────────────┐
   │  循环开始（最多N次）  │
   └─────────┬───────────┘
             │
             ▼
┌────────────────────────────────────────┐
│  Thought（思考阶段）                    │
│  ─────────────────────────────────────│
│  Agent 内心独白：                       │
│  "我需要了解两个角色的信息才能比较。    │
│   先查询孙悟空的资料。"                 │
└────────────┬───────────────────────────┘
             │
             ▼
┌────────────────────────────────────────┐
│  Action（行动阶段）                     │
│  ─────────────────────────────────────│
│  决策：选择工具                          │
│  工具：vector_search                   │
│  参数：query="孙悟空的能力和特点"        │
└────────────┬───────────────────────────┘
             │
             ▼
┌────────────────────────────────────────┐
│  Observation（观察阶段）                │
│  ─────────────────────────────────────│
│  工具返回结果：                         │
│  "孙悟空会七十二变，有金箍棒..."       │
│                                        │
│  Agent评估：                           │
│  "信息不错，但还需要猪八戒的信息"       │
└────────────┬───────────────────────────┘
             │
             ▼
        ┌────────┐
        │ 判断   │  信息充足了吗？
        └───┬┬───┘
            ││
        否  ││  是
            ││
    ┌───────┘└────────┐
    │                 │
    ▼                 ▼
返回循环开始     ┌─────────────┐
（下一轮）       │ Final Answer│
                 │（最终答案）  │
                 └─────────────┘
```

### 1.3 为什么 ReAct 比简单的链式调用强？

**传统链式调用（Chain）：**
```
固定流程：查询 → 向量搜索 → 生成答案
问题：如果搜索结果不好，无法调整
```

**ReAct 框架：**
```
灵活调整：
第1轮：查询A → 结果不满意
第2轮：换个查询B → 结果还可以
第3轮：再查询C补充 → 完美！
生成答案
```

## 二、Thought（思考）阶段：Agent 如何分析问题

### 2.1 思考阶段的核心任务

在思考阶段，Agent 需要回答三个关键问题：

1. **我现在知道什么？**（当前状态）
2. **我还需要知道什么？**（信息缺口）
3. **下一步该做什么？**（行动计划）

### 2.2 思考的输出格式

Agent 的思考是通过 LLM 生成的文本：

```
Thought: 用户问的是孙悟空和猪八戒谁更厉害。这是一个对比性问题，
我需要分别了解两个角色的能力。目前我还没有任何信息，应该先查询
孙悟空的资料。
```

### 2.3 思考的类型

**类型1：任务分解**

```
复杂问题："我们产品过去一个月的市场表现如何？"

Agent思考：
Thought: 这个问题包含多个维度：
1. 销售数据（需要查询CRM系统）
2. 用户反馈（需要查询客服记录）
3. 市场舆情（需要Web搜索）
我先从销售数据开始。
```

**类型2：策略调整**

```
第1轮尝试后：
Thought: 上次搜索"西游记"得到的结果太宽泛，不够具体。
我应该缩小范围，搜索"孙悟空性格特点"。
```

**类型3：信息评估**

```
获取结果后：
Thought: 我已经了解了孙悟空的信息，但要进行对比还需要
猪八戒的信息。当前信息还不够充分，需要继续查询。
```

**类型4：终止判断**

```
Thought: 我现在已经有了：
- 孙悟空的武力、智慧、性格特点
- 猪八戒的武力、智慧、性格特点
信息已经充足，可以进行对比分析并生成答案了。
```

### 2.4 思考的质量如何保证？

通过精心设计的 **System Prompt**（系统提示词）：

```
你是一个专业的RAG Agent。当你思考时，请：
1. 明确说明当前已知信息
2. 指出还缺少什么信息
3. 解释为什么选择某个工具
4. 评估是否需要继续获取信息

示例：
Thought: [当前状态] 我还没有任何关于孙悟空的信息。
[信息缺口] 需要了解孙悟空的能力和特点。
[行动计划] 我将使用vector_search工具查询"孙悟空能力特点"。
```

## 三、Action（行动）阶段：工具的选择与调用

### 3.1 工具系统架构

Agentic RAG 的工具系统就像一个工具箱，每个工具负责特定的任务：

```
┌─────────────────────────────────┐
│         Agent 工具箱             │
├─────────────────────────────────┤
│                                 │
│  🔍 向量搜索工具                 │
│     └─ 从知识库检索相关文档      │
│                                 │
│  🌐 Web搜索工具                 │
│     └─ 从互联网获取最新信息      │
│                                 │
│  🧮 计算器工具                   │
│     └─ 进行数学计算              │
│                                 │
│  📞 API调用工具                 │
│     └─ 调用外部服务              │
│                                 │
│  📊 数据分析工具                 │
│     └─ 分析结构化数据            │
│                                 │
│  ➕ 自定义工具                   │
│     └─ 可扩展...                │
│                                 │
└─────────────────────────────────┘
```

### 3.2 工具的定义格式

每个工具都需要明确定义：名称、功能描述、参数说明

```python
# 工具1：向量搜索
{
    "name": "vector_search",
    "description": "从知识库中搜索相关文档。适用于查询内部文档、产品手册等。",
    "parameters": {
        "query": "搜索查询（必填）",
        "k": "返回文档数量，默认3"
    }
}

# 工具2：Web搜索
{
    "name": "web_search",
    "description": "从互联网搜索最新信息。适用于查询新闻、实时数据等。",
    "parameters": {
        "query": "搜索查询（必填）",
        "max_results": "最大结果数，默认3"
    }
}

# 工具3：计算器
{
    "name": "calculator",
    "description": "进行数学计算。适用于需要精确计算的场景。",
    "parameters": {
        "expression": "数学表达式（必填）"
    }
}
```

### 3.3 Agent 如何选择工具？

**方式1：基于关键词匹配**

```
查询中包含"最新"、"今天"、"现在" → 使用 web_search
查询中包含"计算"、"多少"、"总共" → 使用 calculator
其他情况 → 使用 vector_search
```

**方式2：基于 LLM 推理**

将所有工具的描述告诉 LLM，让它选择：

```
系统：你有以下工具可用：
1. vector_search: 从知识库搜索
2. web_search: 从互联网搜索
3. calculator: 数学计算

用户问题：今天北京天气如何？

Agent决策：
Thought: 这需要实时信息，知识库里没有。
Action: web_search
Action Input: {"query": "北京今天天气"}
```

### 3.4 工具调用的标准格式

Agent 需要输出结构化的行动指令：

```
Action: tool_name
Action Input: {
    "param1": "value1",
    "param2": "value2"
}
```

**示例1：向量搜索**
```
Action: vector_search
Action Input: {
    "query": "孙悟空的能力和特点",
    "k": 3
}
```

**示例2：Web搜索**
```
Action: web_search
Action Input: {
    "query": "2024年诺贝尔物理学奖",
    "max_results": 5
}
```

**示例3：计算器**
```
Action: calculator
Action Input: {
    "expression": "1000 * 12 * 0.95"
}
```

## 四、Observation（观察）阶段：结果评估与迭代

### 4.1 观察阶段的任务

观察阶段要做两件事：

1. **接收工具返回的结果**
2. **评估结果质量**

```
┌──────────────┐
│  工具执行     │
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  返回结果     │
└──────┬───────┘
       │
       ▼
┌──────────────────────┐
│  Agent观察和评估      │
│  ─────────────────── │
│  - 结果是否相关？     │
│  - 信息是否充足？     │
│  - 是否需要补充？     │
└──────┬───────────────┘
       │
       ▼
    判断决策
```

### 4.2 观察的输出格式

```
Observation: [工具返回的原始结果]

[Agent的评估]
```

**示例1：满意的结果**
```
Observation: 孙悟空原本是花果山上的一块仙石孕育而生的石猴，
后来拜菩提祖师为师，学会了七十二变和筋斗云...

Thought: 这个信息很详细，包含了孙悟空的来历和主要能力。
接下来需要查询猪八戒的信息进行对比。
```

**示例2：不满意的结果**
```
Observation: 未找到相关文档。

Thought: 搜索"西游记人物"太宽泛了，没有得到有用的信息。
我应该改用更具体的查询，比如"孙悟空性格特点"。
```

**示例3：需要补充的结果**
```
Observation: 孙悟空会七十二变。

Thought: 信息太简略了，只提到了一个能力。我需要更全面的信息，
包括他的武器、师父、性格等。让我再查询一次。
```

### 4.3 质量评估的标准

Agent 评估结果时考虑三个维度：

**1. 相关性（Relevance）**
```
问题：孙悟空是谁？
结果："猪八戒是天蓬元帅..."
评估：不相关 ✗
```

**2. 完整性（Completeness）**
```
问题：介绍孙悟空的主要能力
结果："会七十二变"
评估：不完整，还应该包括金箍棒、筋斗云等 ⚠️
```

**3. 可信度（Reliability）**
```
结果来自：公司内部文档 → 可信度高 ✓
结果来自：未知网站 → 需要交叉验证 ⚠️
```

### 4.4 迭代策略

如果结果不满意，Agent 可以采取以下策略：

**策略1：重写查询（Query Rewriting）**
```
第1次：query = "西游记"          （太宽泛）
第2次：query = "西游记孙悟空"    （更具体）
第3次：query = "孙悟空能力特点"  （最精确）
```

**策略2：换工具**
```
第1次：vector_search → 没找到     （知识库没有）
第2次：web_search → 找到了 ✓     （网上有）
```

**策略3：分解查询**
```
原查询："孙悟空和猪八戒的对比"
↓
分解：
查询1："孙悟空的特点"
查询2："猪八戒的特点"
最后：整合对比
```

## 五、Prompt 工程：让 Agent 聪明起来

### 5.1 什么是 Prompt 工程？

Prompt 就是给 LLM 的"指令手册"。好的 Prompt 能让 Agent 表现得更智能。

**差的 Prompt：**
```
你是一个AI助手，帮我回答问题。
```

**好的 Prompt：**
```
你是一个专业的RAG Agent，使用ReAct框架工作。

工作流程：
1. Thought: 分析问题，制定计划
2. Action: 选择工具并执行
3. Observation: 评估结果
4. 重复2-3直到信息充足
5. 生成最终答案

可用工具：
- vector_search: 从知识库检索
- web_search: 从互联网搜索

输出格式：
Thought: [你的思考]
Action: [工具名]
Action Input: {参数}
```

### 5.2 System Prompt 的结构

一个完整的 System Prompt 包含：

```
┌─────────────────────────────┐
│  1. 角色定义                 │
│     "你是一个RAG Agent"      │
├─────────────────────────────┤
│  2. 工作流程                 │
│     "使用ReAct框架..."       │
├─────────────────────────────┤
│  3. 工具列表                 │
│     "可用工具：..."          │
├─────────────────────────────┤
│  4. 输出格式                 │
│     "Thought: ... Action:..."│
├─────────────────────────────┤
│  5. 约束条件                 │
│     "最多迭代5次..."         │
├─────────────────────────────┤
│  6. 示例（Few-shot）         │
│     "示例1: ..."             │
└─────────────────────────────┘
```

### 5.3 Few-shot Learning：通过示例引导

给 Agent 看几个好例子，它就知道该怎么做：

```
System: 你是RAG Agent，使用ReAct框架。以下是示例：

示例1:
用户: 孙悟空是谁？
Thought: 这是关于《西游记》人物的简单查询，使用向量搜索即可。
Action: vector_search
Action Input: {"query": "孙悟空", "k": 3}
Observation: 孙悟空是《西游记》中的主角...
Thought: 信息充足，可以生成答案。
Final Answer: 孙悟空是...

示例2:
用户: 今天北京天气如何？
Thought: 这需要实时信息，知识库里没有，应该用Web搜索。
Action: web_search
Action Input: {"query": "北京今天天气", "max_results": 3}
Observation: 今天北京晴，15-25度...
Thought: 得到了实时天气信息，可以回答了。
Final Answer: 今天北京天气...

现在开始处理用户的查询。
```

### 5.4 Prompt 的优化技巧

**技巧1：明确约束**
```
约束条件：
- 最多迭代5次，避免无限循环
- 每次思考必须说明理由
- 如果连续2次搜索无结果，就坦诚告知用户
```

**技巧2：输出格式标准化**
```
严格按照以下格式输出，不要有任何额外内容：

Thought: [你的思考，一句话]
Action: [工具名]
Action Input: {"param": "value"}

或者：

Thought: [思考]
Final Answer: [最终答案]
```

**技巧3：提供思考框架**
```
思考时请回答三个问题：
1. 我现在知道什么？
2. 我还需要知道什么？
3. 下一步该怎么做？

示例：
Thought:
[已知] 暂无信息
[需要] 孙悟空的资料
[行动] 使用vector_search查询
```

## 六、成本控制：让 Agentic RAG 更经济

### 6.1 成本来源分析

Agentic RAG 的成本主要来自：

```
每次查询的成本 =
  LLM推理次数 × 单次调用成本
  + 工具调用成本（API费用）
```

**示例对比：**

| 场景 | LLM调用次数 | 成本（GPT-4） |
|-----|-----------|--------------|
| Traditional RAG | 1次 | $0.005 |
| Agentic RAG（简单查询） | 2-3次 | $0.015 |
| Agentic RAG（复杂查询） | 5-8次 | $0.040 |

### 6.2 成本控制策略

**策略1：智能路由**

不是所有问题都需要 Agentic RAG：

```
┌──────────────┐
│  用户查询     │
└──────┬───────┘
       │
       ▼
  ┌────────┐
  │ 路由器 │ 判断查询复杂度
  └───┬┬───┘
      ││
  简单││复杂
      ││
  ┌───┘└────┐
  │          │
  ▼          ▼
Traditional  Agentic
RAG (70%)    RAG (30%)
成本: $0.35  成本: $1.20
────────────────────────
总成本: $1.55 (节省56%)
vs 全部用Agentic: $3.60
```

**策略2：限制迭代次数**

```python
max_iterations = 5  # 最多5轮迭代
```

这样可以：
- 避免无限循环
- 控制最大成本
- 5轮通常够用（覆盖95%的查询）

**策略3：缓存常见查询**

```python
# 缓存机制
if query in cache:
    return cache[query]  # 直接返回，不调用LLM
else:
    result = agent.query(query)
    cache[query] = result
```

缓存可以节省：
- 重复查询的成本（节省100%）
- 响应时间（从5秒降到0.1秒）

**策略4：使用更便宜的模型**

```
推理阶段（Thought）：使用更便宜的模型（如 GPT-3.5）
最终生成（Final Answer）：使用更好的模型（如 GPT-4）

成本对比：
全部GPT-4: $0.040
混合模式:  $0.020（节省50%）
```

**策略5：批量处理**

```python
# 一次获取多个文档，而不是多次查询
docs = vector_search(query, k=5)  # 一次获取5个

而不是：
doc1 = vector_search(query, k=1)
doc2 = vector_search(query, k=1)  # 多次调用
...
```

### 6.3 性能监控指标

需要追踪以下指标来优化成本：

```
┌───────────────────────────┐
│  核心监控指标              │
├───────────────────────────┤
│ 1. 平均迭代次数            │
│    目标: < 3次              │
│                           │
│ 2. 平均响应时间            │
│    目标: < 8秒              │
│                           │
│ 3. 平均成本                │
│    目标: < $0.02/查询       │
│                           │
│ 4. 准确率                  │
│    目标: > 85%             │
│                           │
│ 5. 缓存命中率              │
│    目标: > 30%             │
└───────────────────────────┘
```

## 本讲总结

**核心要点：**

1. **ReAct 框架**：Think（思考）→ Act（行动）→ Observe（观察）的循环
2. **Thought 阶段**：分析当前状态，制定下一步计划
3. **Action 阶段**：选择合适的工具并调用
4. **Observation 阶段**：评估结果，决定是否继续
5. **工具系统**：向量搜索、Web搜索、计算器等可扩展工具箱
6. **Prompt 工程**：通过精心设计的提示词让 Agent 更智能
7. **成本控制**：智能路由、限制迭代、缓存、模型选择

**技术本质：**

```
ReAct 框架 = 人类问题解决方式的形式化
Prompt 工程 = 给 AI 的"操作手册"
工具系统 = AI 的"能力边界"
成本控制 = 智能与经济的平衡
```
