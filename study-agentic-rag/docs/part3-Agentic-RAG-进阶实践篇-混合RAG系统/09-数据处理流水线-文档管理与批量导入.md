在前面的讲解中，我们都是用简单的`sample_documents`列表来测试系统。但在真实场景中，你需要处理成百上千的文档。

## 一、为什么需要数据处理流水线？

### 真实场景的挑战

**示例：构建企业知识库问答系统**

```
原始数据：
├── 产品手册/
│   ├── 产品A手册.pdf  (50页)
│   ├── 产品B手册.docx (80页)
│   └── FAQ.txt        (1000行)
├── 技术文档/
│   ├── API文档.md
│   └── 架构设计.md
└── 政策文档/
    ├── 隐私政策.txt
    └── 用户协议.txt

总计：300+个文档，50万+字
```

**直接导入的问题：**
1. ❌ 文件格式不统一（PDF/Word/Markdown/TXT）
2. ❌ 单个文档太大（超过LLM上下文限制）
3. ❌ 包含无效内容（空格、乱码、格式符）
4. ❌ 语义完整性被破坏（生硬切块）
5. ❌ 没有元数据（无法溯源）

### 数据处理流水线的价值

```
┌─────────────────────────────────────────────────┐
│           数据处理流水线                           │
│                                                 │
│  原始文档                                         │
│     ↓                                           │
│  1️⃣ 文档加载 (DocumentLoader)                    │
│     支持多格式、递归目录扫描                       │
│     ↓                                           │
│  2️⃣ 文本清洗 (TextProcessor)                     │
│     移除无效字符、标准化格式                       │
│     ↓                                           │
│  3️⃣ 智能分块 (TextChunker)                       │
│     固定大小 or 语义分块                          │
│     ↓                                           │
│  4️⃣ 批量导入                                      │
│     生成嵌入、存储向量                            │
│     ↓                                           │
│  向量数据库                                       │
└─────────────────────────────────────────────────┘
```

## 二、文本清洗（TextProcessor）

### 为什么需要清洗？

**原始文本的问题：**

```python
# 原始文本（来自复制粘贴或OCR）
raw_text = """
《西游记》是中国古代第一部浪漫主义章回体长篇神魔小说。

           现存明刊百回本《西游记》均无作者署名。


清代学者吴玉搢等首先提出《西游记》作者是明代吴承恩。
"""

# 问题：
- 多余的空白符
- 不规则的换行
- 特殊字符和符号
```

### 清洗方法实现

```python
"""
数据预处理和分块工具
Data Processing and Chunking Utilities
"""

import os
import re
from typing import List
from pathlib import Path
import config


class TextProcessor:
    """文本预处理器"""

    @staticmethod
    def clean_text(text: str) -> str:
        """
        清洗文本

        Args:
            text: 原始文本

        Returns:
            清洗后的文本
        """
        # 步骤1: 移除多余空白
        text = re.sub(r'\s+', ' ', text)

        # 步骤2: 移除特殊字符（保留中文、英文、数字、标点）
        text = re.sub(r'[^\u4e00-\u9fa5a-zA-Z0-9，。！？；：、""''（）《》\n]', '', text)

        # 步骤3: 标准化换行
        text = re.sub(r'\n+', '\n', text)

        return text.strip()

    @staticmethod
    def split_by_sentence(text: str) -> List[str]:
        """
        按句子分割文本

        Args:
            text: 输入文本

        Returns:
            句子列表
        """
        # 中文句子分隔符
        sentences = re.split(r'[。！？；]', text)
        return [s.strip() for s in sentences if s.strip()]
```

**为什么这么写？**

1. **为什么用 `re.sub(r'\s+', ' ', text)`？**
   - `\s+`：匹配一个或多个空白符（空格、Tab、换行）
   - 替换为单个空格，统一格式
   - 去除文档中的多余空白

   ```python
   # 示例
   "文本  \t\n   内容" → "文本 内容"
   ```

2. **为什么保留特定字符？**
   - `\u4e00-\u9fa5`：中文字符范围
   - `a-zA-Z0-9`：英文和数字
   - `，。！？`：常用标点
   - 其他字符（如�、□）通常是乱码

3. **为什么提供 `split_by_sentence()`？**
   - 后续语义分块需要
   - 按句子切分保证语义完整
   - 中文分隔符：。！？；

## 三、智能分块（TextChunker）

### 为什么需要分块？

**问题场景：**

```
整篇文档：10,000字
LLM上下文限制：4,096 tokens ≈ 3,000字
嵌入模型限制：512 tokens ≈ 400字

→ 必须分块！
```

### 两种分块策略

#### 策略1：固定大小分块

```python
class TextChunker:
    """文本分块器"""

    def __init__(
        self,
        chunk_size: int = config.CHUNK_SIZE,  # 500字符
        chunk_overlap: int = config.CHUNK_OVERLAP  # 50字符
    ):
        """
        初始化分块器

        Args:
            chunk_size: 分块大小（字符数）
            chunk_overlap: 分块重叠（字符数）
        """
        self.chunk_size = chunk_size
        self.chunk_overlap = chunk_overlap

    def chunk_text(self, text: str) -> List[str]:
        """
        分割文本为固定大小的块

        Args:
            text: 输入文本

        Returns:
            文本块列表
        """
        chunks = []
        start = 0
        text_length = len(text)

        while start < text_length:
            # 计算结束位置
            end = min(start + self.chunk_size, text_length)

            # 提取文本块
            chunk = text[start:end].strip()

            if chunk:
                chunks.append(chunk)

            # 移动起始位置（考虑重叠）
            start += self.chunk_size - self.chunk_overlap

        return chunks
```

**为什么这么写？**

1. **为什么需要 `chunk_overlap`（重叠）？**
   - 避免语义在切分点被破坏
   - 示例：

   ```
   块1: "孙悟空拜师学艺，学得七|"
   块2: "|十二变和筋斗云等神通"

   有重叠:
   块1: "孙悟空拜师学艺，学得七十二变和筋|"
   块2: "|七十二变和筋斗云等神通"  ← 保留上下文
   ```

2. **为什么用滑动窗口？**
   - `start += chunk_size - chunk_overlap`
   - 每次移动450字符（500-50）
   - 保证50字符重叠

3. **为什么用固定大小？**
   - ✅ 简单高效
   - ✅ 可预测性强
   - ❌ 可能破坏语义边界

**固定分块示例：**

```python
text = "《西游记》是中国古代第一部浪漫主义章回体长篇神魔小说。现存明刊百回本《西游记》均无作者署名。清代学者吴玉搢等首先提出《西游记》作者是明代吴承恩。"

chunker = TextChunker(chunk_size=50, chunk_overlap=10)
chunks = chunker.chunk_text(text)

# 结果
块1: "《西游记》是中国古代第一部浪漫主义章回体长篇神魔小说。现存明刊百回本《西游记》均无作者"
块2: "《西游记》均无作者署名。清代学者吴玉搢等首先提出《西游记》作者是明代吴承恩。"
```

#### 策略2：语义分块

```python
    def chunk_by_semantic(self, text: str, max_chunk_size: int = None) -> List[str]:
        """
        按语义分割文本（基于句子边界）

        Args:
            text: 输入文本
            max_chunk_size: 最大块大小

        Returns:
            语义分块列表
        """
        if max_chunk_size is None:
            max_chunk_size = self.chunk_size

        # 分割成句子
        sentences = TextProcessor.split_by_sentence(text)

        chunks = []
        current_chunk = ""

        for sentence in sentences:
            # 如果当前块加上新句子不超过最大大小
            if len(current_chunk) + len(sentence) <= max_chunk_size:
                current_chunk += sentence + "。"
            else:
                # 保存当前块，开始新块
                if current_chunk:
                    chunks.append(current_chunk.strip())
                current_chunk = sentence + "。"

        # 添加最后一个块
        if current_chunk:
            chunks.append(current_chunk.strip())

        return chunks
```

**为什么这么写？**

1. **为什么按句子边界分块？**
   - 保证语义完整性
   - 每个块是完整的句子
   - 更符合人类阅读习惯

2. **为什么用贪心算法？**
   - 尽可能多放句子到当前块
   - 直到超过max_chunk_size
   - 简单高效

3. **为什么保留句号？**
   - `sentence + "。"`
   - 恢复句子结束符
   - 保持文本自然性

**语义分块示例：**

```python
text = "《西游记》是中国古代第一部浪漫主义章回体长篇神魔小说。现存明刊百回本《西游记》均无作者署名。清代学者吴玉搢等首先提出《西游记》作者是明代吴承恩。"

chunks = chunker.chunk_by_semantic(text, max_chunk_size=100)

# 结果
块1: "《西游记》是中国古代第一部浪漫主义章回体长篇神魔小说。现存明刊百回本《西游记》均无作者署名。"
块2: "清代学者吴玉搢等首先提出《西游记》作者是明代吴承恩。"
```

### 两种策略对比

| 维度 | 固定大小分块 | 语义分块 |
|------|------------|---------|
| **实现难度** | 简单 | 中等 |
| **语义完整性** | 较差 | 很好 |
| **块大小** | 完全一致 | 有波动 |
| **处理速度** | 快 | 稍慢（需解析句子） |
| **适用场景** | 通用 | 中文文档 |
| **推荐度** | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ |

**推荐使用语义分块**，除非有特殊要求。

## 四、文档加载（DocumentLoader）

### 批量加载文档

```python
class DocumentLoader:
    """文档加载器"""

    @staticmethod
    def load_text_file(file_path: str) -> str:
        """
        加载文本文件

        Args:
            file_path: 文件路径

        Returns:
            文件内容
        """
        try:
            with open(file_path, 'r', encoding='utf-8') as f:
                return f.read()
        except UnicodeDecodeError:
            # 尝试其他编码
            with open(file_path, 'r', encoding='gbk') as f:
                return f.read()

    @staticmethod
    def load_directory(directory: str, extensions: List[str] = None) -> List[dict]:
        """
        加载目录中的所有文档

        Args:
            directory: 目录路径
            extensions: 文件扩展名列表

        Returns:
            文档列表 [{"path": ..., "content": ...}, ...]
        """
        if extensions is None:
            extensions = ['.txt', '.md']

        documents = []
        path = Path(directory)

        for file_path in path.rglob('*'):
            if file_path.is_file() and file_path.suffix in extensions:
                content = DocumentLoader.load_text_file(str(file_path))
                documents.append({
                    "path": str(file_path),
                    "filename": file_path.name,
                    "content": content
                })

        return documents
```

**为什么这么写？**

1. **为什么处理编码问题？**
   - UTF-8是标准，但中文文档可能是GBK
   - 先尝试UTF-8，失败后尝试GBK
   - 避免乱码和读取失败

2. **为什么用 `rglob('*')`？**
   - 递归搜索所有子目录
   - `glob('*')`只搜索当前目录
   - 适合复杂的目录结构

3. **为什么返回dict而不是字符串？**
   - 保留文档元信息（路径、文件名）
   - 便于溯源和调试
   - 灵活的数据结构

**使用示例：**

```python
docs = DocumentLoader.load_directory("./data/documents", extensions=['.txt', '.md'])

# 结果
[
    {
        "path": "./data/documents/FAQ.txt",
        "filename": "FAQ.txt",
        "content": "Q: 什么是RAG?\nA: 检索增强生成..."
    },
    {
        "path": "./data/documents/manual.md",
        "filename": "manual.md",
        "content": "# 产品手册\n\n## 功能介绍..."
    }
]
```

## 五、完整流水线（DataPipeline）

### 整合所有模块

```python
class DataPipeline:
    """完整的数据处理流水线"""

    def __init__(self):
        """初始化流水线"""
        self.processor = TextProcessor()
        self.chunker = TextChunker()

    def process_document(self, text: str, use_semantic: bool = True) -> List[str]:
        """
        处理单个文档

        Args:
            text: 原始文本
            use_semantic: 是否使用语义分块

        Returns:
            处理后的文本块列表
        """
        # 1. 清洗文本
        cleaned_text = self.processor.clean_text(text)

        # 2. 分块
        if use_semantic:
            chunks = self.chunker.chunk_by_semantic(cleaned_text)
        else:
            chunks = self.chunker.chunk_text(cleaned_text)

        return chunks

    def process_directory(
        self,
        input_dir: str,
        output_dir: str = None,
        use_semantic: bool = True
    ) -> List[str]:
        """
        批量处理目录中的文档

        Args:
            input_dir: 输入目录
            output_dir: 输出目录（可选）
            use_semantic: 是否使用语义分块

        Returns:
            所有文本块
        """
        # 加载文档
        documents = DocumentLoader.load_directory(input_dir)

        all_chunks = []

        for doc in documents:
            print(f"处理文档: {doc['filename']}")

            # 处理文档
            chunks = self.process_document(doc['content'], use_semantic)
            all_chunks.extend(chunks)

            # 可选：保存处理后的块
            if output_dir:
                os.makedirs(output_dir, exist_ok=True)
                output_file = os.path.join(
                    output_dir,
                    f"{os.path.splitext(doc['filename'])[0]}_chunks.txt"
                )
                with open(output_file, 'w', encoding='utf-8') as f:
                    for i, chunk in enumerate(chunks, 1):
                        f.write(f"=== 块 {i} ===\n{chunk}\n\n")

                print(f"  → 生成 {len(chunks)} 个文本块")

        print(f"\n总共处理: {len(all_chunks)} 个文本块")
        return all_chunks
```

**为什么这么写？**

1. **为什么流水线方式？**
   - 模块化设计，职责清晰
   - 易于扩展（添加新处理步骤）
   - 便于复用

2. **为什么支持输出目录？**
   - 调试时查看处理结果
   - 人工审核分块质量
   - 生成中间文件

3. **为什么用 `extend()` 而不是 `append()`？**
   - `extend(chunks)`：把列表中的元素逐个添加
   - `append(chunks)`：把整个列表作为一个元素添加
   - 我们需要扁平化的块列表

import time
from watchdog.observers import Observer
from watchdog.events import FileSystemEventHandler

class DocumentHandler(FileSystemEventHandler):
    def __init__(self, rag_engine, pipeline):
        self.rag_engine = rag_engine
        self.pipeline = pipeline

    def on_created(self, event):
        if event.src_path.endswith(('.txt', '.md')):
            print(f"新文档: {event.src_path}")

            # 读取并处理
            with open(event.src_path, 'r', encoding='utf-8') as f:
                content = f.read()

            chunks = self.pipeline.process_document(content)

            # 导入RAG
            self.rag_engine.add_documents(chunks)

            print(f"✅ 导入 {len(chunks)} 个块")

# 启动监听
observer = Observer()
observer.schedule(
    DocumentHandler(rag_engine, pipeline),
    path="./data/documents",
    recursive=True
)
observer.start()

print("监听文档变化...")
try:
    while True:
        time.sleep(1)
except KeyboardInterrupt:
    observer.stop()

## 八、配置参数调优

### config.py中的分块参数

```python
# 分块参数
CHUNK_SIZE = 500  # 分块大小（字符数）
CHUNK_OVERLAP = 50  # 分块重叠（字符数）
```

### 如何选择参数？

**`CHUNK_SIZE` 选择：**

| 大小 | 优点 | 缺点 | 适用场景 |
|------|------|------|---------|
| 100-300 | 精确匹配 | 上下文不足 | 短问答、FAQ |
| 500-800 | **平衡** | - | **推荐，通用** |
| 1000+ | 上下文丰富 | 检索不精确 | 长文档分析 |

**`CHUNK_OVERLAP` 选择：**

```
overlap = chunk_size * 10%  # 通常10%
```

- 太小（<5%）：语义可能断裂
- 适中（10-15%）：平衡效果和成本
- 太大（>20%）：重复内容过多
